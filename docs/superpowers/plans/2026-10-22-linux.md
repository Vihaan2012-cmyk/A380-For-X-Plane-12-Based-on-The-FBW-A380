## Linux-specific failures and causes

1. Plugin lib tests do not link on Linux: `rust-lld: unable to find library -lkernel32`. Unguarded `#[link(name = "kernel32")]` extern blocks in `src/diag.rs:456`, `src/display/gl.rs:144`, `src/js_bridge.rs:775`, `src/net.rs:117`, and `#[link(name = "psapi")]` in `src/navdata/tests.rs:18`. Same failure with and without `--features js`. The crate itself compiles on Linux (it reached the link step). Owners: wrap the blocks and their callers in `#[cfg(windows)]` with a non-Windows stub (net.rs needs a non-WinHTTP backend on Linux: libcurl or a pure-Rust client). Next pass after that will show any undefined symbols the guards leave.
2. `native-displays` feature: build.rs panics on non-Windows by design (plan Task 7); CMake + Skia build for Linux exists in a380-displays and is the template.
3. tcas oracle: 5/74 scenarios differed in `closureRate` by ~2e-9 kt at near-zero closure (cancellation of two slant distances; glibc trig vs the recorded V8 values). Fixed in the test: absolute floor 1e-9 -> 1e-6 (GENERIC tolerance).
4. deep_electrical golden digests (recorded on Windows 13 Oct) diverge at frame 7 on Linux. The uncommitted edits in src/deep/electrical only add save/restore, so the probable cause is libm (exp/powf in network.rs and sources.rs, 10 calls) giving different last bits. Confirm by running the test on Windows once src/deep compiles again; if Windows passes, the digest is platform-dependent and needs either a tolerance-based compare or `libm`-crate math in the deep areas.
5. Hard-coded Windows oracle paths make oracle tests silently skip on Linux (they pass with zero comparisons): fms_data `tests/oracle.rs:7`, fms_lnav `tests/oracle.rs:4` and `tests/flight.rs:4` (backslash paths), fms_vnav `tests/oracle.rs:8` and `tests/predictions.rs:12`, oans `tests/logic.rs:34`, fws `src/compare.rs:239,243` (has env overrides; defaults use backslashes). Owners: add env overrides like `FMS_ORACLE_DIR`.
6. src (plugin) also has absolute `D:\fbw-aircraft\...` test inputs: `src/fuel_network.rs:2517`, `src/fuel_transfer.rs:730`, `src/js_worker.rs:419`, `src/ecam_patches/ecl.rs:199`, `src/deep/ecam/patches.rs:172`, `src/deep/ecam/fbw_tests.rs:36`, `src/navdata/tests.rs:16`. They will skip or fail on Linux; use `CARGO_MANIFEST_DIR`-relative `../fbw-aircraft/...` paths as circuits.rs and fuel.rs already do.
7. Not Linux-specific but blocks `cargo test` per crate everywhere: deep_systems and mfd_tree lack `[workspace]` and are not listed in the root manifest.
8. CRLF: files are copied byte for byte, so CRLF-assumption bugs would only show on a git clone with LF checkout. `oit_pages` tests feed `\r\n` deliberately; no test failed on line endings.
