**Goal:** Ship the A380 port for X-Plane 11.55 from the same sources as the X-Plane 12 build: one plugin binary that adapts at run time, and a second aircraft build from the converter.

**Architecture:** The plugin detects X-Plane 11 at start and installs an *XP12 shim*: it registers the 42 X-Plane 12 datarefs and 20 commands it uses under their XP12 names, backed by XP11 equivalents with unit conversion. Every other module, the SASL Lua and the OBJs then run unchanged. Features built on XP12-only SDK calls (avionics devices, `XPLMSound`, the weather API, METAR) get XP11 backends in later phases. The converter gains `--target xp11`, which writes an XP11 `.acf` from an XP11 template, XP11 light names, and no XP12 device manipulators.

## Phases

1. **Loads and flies** (this document, detailed below). XP11 shim, converter `--target xp11`, XP11 install. Done when: the A380 loads in XP11.55, systems run, cockpit switches work, it taxis, takes off and lands under FBW control laws. Screens and FBW cockpit audio stay blank or silent.
2. **Screens on the panel texture.** The display module gains a second backend. On XP12 it keeps avionics devices; on XP11 it draws XPHFBW frames into the 3D panel texture in `xplm_Phase_Gauges`. The converter emits `ATTR_cockpit_region` (up to 4 × 2048²) and remaps each screen mesh's UVs into a panel atlas. Clicks use `ATTR_manip_command` spots plus `sim/graphics/view/click_3d_x_pixels`/`_y_pixels`. Popouts use `XPLMCreateWindowEx` (`xplm_WindowPopOut`, XP11.20+), and keyboard focus uses `XPLMTakeKeyboardFocus` with the existing key sniffer. Budget: the FCU (2560×1280) and EFB (1430×1000) are drawn at half size; the other screens at full size fit in 16.7 MP. Gets its own plan.
3. **Cockpit audio.** A `PcmOut` trait in `src/sound`, with the XP12 `XPLMPlayPCMOnBus` backend and an XP11 `cpal` (WASAPI) backend. Volume follows `sim/operation/sound/master_volume_ratio`. `sound_levels.rs` skips FMOD volume groups when `XPLMGetFMODStudio` is absent. Check that the FTSiM+ banks load from `fmod/A380.snd` in XP11.
4. **Weather, WXR, METAR.** The `wxr` module builds `XPLMWeatherInfo_t`-equivalent samples from XP11's three cloud layers (`sim/weather/cloud_*[0..2]`), wind layers and `rain_percent`. METAR is read from XP11's `METAR.rwx` in the X-Plane root (written when real weather is on).
5. **Flight model in XP11.** XP11 has no wing flex and a different aero solver. Rebuild the airframe on the XP11 template, tune in Plane Maker 11 against the same targets as XP12 (TO N1 83.8 %, Vr, climb rate at MTOW, cruise fuel flow, approach pitch). Use the existing flight-test checklists.
6. **Packaging.** The installer fork adds an `xplane11` simulator (`%LOCALAPPDATA%/x-plane_install_11.txt`) and an "A380 for X-Plane 11" package built by the release tooling from the XP11 install. Also: licence check of the XP11 template `.acf` (same stance as the XP12 build's A330 template) and the `THIRD_PARTY_*` files.

pub fn cloud_at(alt_m: f32, layers: &[(f32, f32, f32); 3]) -> (f32, f32, f32) {
    let live = layers.iter().filter(|l| l.2 > 0.0 && l.1 > l.0);
    let inside = live.clone().find(|l| alt_m >= l.0 && alt_m <= l.1);
    let above = live.clone().filter(|l| l.0 > alt_m).min_by(|a, b| a.0.total_cmp(&b.0));
    match inside.or(above).or_else(|| live.max_by(|a, b| a.1.total_cmp(&b.1))) {
        Some(&(base, tops, cov)) => (base, tops, cov / 6.0 * 100.0),
        None => (0.0, 0.0, 0.0),
    }
}
