# FMS performance data entry (crates/fms_data)

Date: 22 October 2026. Source: FlyByWire `A380FlightPlanPerformanceData.ts`, `FlightPlanPerformanceData.ts`, `FlightPlan.ts` (origin/destination defaults, constraint reconcile), `FlightPlanService.ts` (approach wind), A380X MFD `FlightManagementComputer.ts` (`trySetCruiseFl`, CI 0/LRC default, secondary activation), `FmcAircraftInterface.ts` (`toSpeedsChecks`), `FmsFlightPlanPage.tsx` (runway change clears V speeds), `MfdFmsPerf.tsx`, `MfdFmsFuelLoad.tsx`, `MfdFmsInit.tsx` and `DataEntryFormats.tsx` (entry ranges), `PerformanceConstants.ts` (limits).

## What the crate holds

- `data.rs`: `PerformanceData`, every A380 field with FBW's pilot / default / database / calculated split and FBW's defaults. Computed getters (`thrust_reduction_altitude`, `transition_level`, `minimum_destination_fuel_on_board`, ...) use JS `Math.round` quanta. Weights in tonnes like FBW; entries take kg.
- `entry.rs`: `Entry` (one variant per MFD field), `EntryContext` (phase, active/copy, engines started, destination, FCU altitude, weight-variant MZFW, rec max FL), `apply()` with FBW's ranges and gates:
  - TO page fields locked on the active plan (or its copy) from the take-off phase on.
  - CI 0..999, locked in LRC or from descent. CRZ FL `trySetCruiseFl` (held at FCU level in climb..approach, NEW CRZ ALT in cruise/descent/approach, CRZ FL ABOVE MAX FL).
  - ZFW 270..373 t (MZFW from the weight variant when given), ZFWCG 23..48, neither clearable. Block, taxi, route reserve (fuel and % clear each other), altn, final (fuel and time clear each other), min dest FOB, pax, trip wind.
  - V1/VR/V2/Vapp/noise speed 90..340 kt. Flex 0..99 with the `A32NX_AIRLINER_TO_FLEX_TEMP` 0 / 0.1 rule. DERATED power setting refused (FBW disables that radio button). THS FOR 0..99.9, clear/0 ignored. Packs/anti-ice after engine start raise CHECK T.O. DATA.
  - QNH 745..1100 hPa or 22.00..32.48 inHg, clear ignored. Temp -99..99. Wind 0..359 deg (stored mod 360) / 0..250 kt, needs a destination, sets/deletes the ground descent wind (as an `Effect`). Baro min 0..43100, DH 1..43100 or 0 = NO DH.
  - `validate_wind`: FBW `WindAltitudeFormat` (no ground altitude: <= 400 ft out of range; result raised to ground).
- `defaults.rs`: origin/destination defaults (elevation + `CONFIG_THR_RED_ALT` / `CONFIG_ACCEL_ALT` / `CONFIG_ENG_OUT_ACCEL_ALT`, 1500 ft default; navdata TA/TL; pilot values cleared; destination change drops descent winds), thrust-reduction/acceleration reconcile against the lowest climb constraint, `pipe_to` (secondary follows active; weights only before engine start), CI 0 + LRC when a destination has no CI.
- `checks.rs`: `TakeoffChecks` (runway change clears V1/VR/V2 and keeps them as "to be confirmed", CHECK T.O. DATA cleared once VR is back; edge-triggered V1/VR/V2 DISAGREE; discrete word 3 bits 16/17/18; secondary activation CHECK T.O. DATA and CHECK ZFW).
- `command.rs` / `service.rs`: `Command` and `PerfDataStore::execute`. Events: `Changed(<FBW key>)` (FBW publishes `flightPlan.setPerformanceData.<key>`), `Message`, `MessageCleared`, `Effect`.

## Integration into crates/fms (for its owner)

`crates/fms/src/plan.rs` has a partial `PerformanceData`; `crates/fms/src/winds.rs` owns wind entries. Suggested wiring, not done here:

1. Add `fms_data = { path = "../fms_data" }` to `crates/fms/Cargo.toml`.
2. Replace `FlightPlan.performance` with `fms_data::PerformanceData` (field names match; the existing fields are a subset), or keep a `PerfDataStore` in `Fms` keyed by plan slot and copy it in `copy`/`swap`/`delete`.
3. `service::Command::PerfData(fms_data::Command)`: in `Fms::execute`, build `EntryContext` from `AircraftState` (phase, engines started, FCU altitude) and the target plan (destination, its elevation), call `PerfDataStore::execute`, then act on the effects:
   - `Effect::Wind(SetWind|DeleteWind|DeleteAllWinds)` -> `plan.winds.set_climb_wind_entry` / `set_descent_wind_entry(.., destination_mag_var)` / `add_cruise_wind_entry` / delete calls.
   - `SetDescentGroundWind` -> `set_descent_wind_entry(Some(0.), entry, mag_var)` with the magnetic direction converted to true at the destination.
   - `DeleteDescentWindAt(alt)`, `DeleteDescentWinds`.
   - `AirlinerFlexTemp`, `CruiseLevelUpdated` -> host variables.
4. Call `OriginChanged` / `DestinationChanged` from `NewCityPair`, `NewDest` and the uplink; `OriginRunwayChanged` after `SetOriginRunway` on the active plan; `ReconcileWithClimbConstraints` after `SetPilotAltitudeConstraint` and procedure changes; `SecondaryActivated` from `ActiveAndSecondarySwap`; `PerfDataStore::update` on each FMS tick for the V-speed bits.
5. AI F/O (`crates/ai_fo`) and the MFD pages send `Command::Enter { plan, entry }`; MFD pages parse text with `crates/mfd_pages_c/src/entry.rs` formats and then send typed entries.
