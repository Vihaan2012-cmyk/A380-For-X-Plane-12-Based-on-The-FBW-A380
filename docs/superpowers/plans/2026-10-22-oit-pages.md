# Native OIT page trees (crates/oit_pages)

Goal: the A380X OIT DOM as pure Rust functions, model in, `mfd_tree::Node` out, JSON identical in structure to what dom2tree gives for the live OIT, for the native OIT painter (oitx).

## Crate shape

- `widgets`: button, icon button, page selector, input field, dropdown, radio group.
- `navigator`: AVNCS folder / file tree nodes.
- `perf_common`: units and formatters from OitFltOpsPerfCommon.ts.
- `flt_ops`: `FltOpsPage` (menu, flt folder, charts, status, T.O PERF, AOC, other) and each page function.
- `shell`: `OitModel` and `build()` giving the whole `div#OIT_CONTENT` (display unit, FLT OPS container, AVNCS container).
- `bin/oit_build`: model JSON in, tree JSON out.
- `tools/capture_models.py`: parses each v15 capture into a model (documented below), builds, runs compare.py.

## Models from captures

Where no other source exists the model is read back from the capture text: widget flags from classes (editing, valueSelected, mandatory, disabled, opened, hidden), numbers from the displayed strings (weights from "300.0 T", QNH from "1013 HPA", wind from "000°T/000KT"), OFP section bodies other than the selected one are a single space (only the selected section body is drawn). Runway data is absent in every capture, so the runway-dependent rows show their placeholders.

## Proof

`python tools/capture_models.py [filter]` writes `E:/fbw-build/oit-pages/<capture>.model.json` and `<capture>.json`, then runs `tools/pagetree/compare.py <json> <dom> id=OIT_CONTENT`. compare.py checks tag, id, value, class set and text; inline styles and SVG shapes are not compared.

## Added 22 Oct (second pass)

Sources translated: `OIT/System/PerfModel.ts` (src/perf_model.rs), `OIT/System/InFlightPerf.ts` (src/inflight_model.rs), the SimBrief TLR parsing and OIS-model result code of `OitFltOpsTakeoffPerformance.tsx` (src/to_compute.rs), `OitFltOpsLandingPerformance.tsx` and `OitFltOpsInFlightPerf.tsx` (src/perf_pages.rs), `OitFltOpsLoadsheet.tsx` with `System/Loadsheet.ts`, `OitFltOpsOpsLibrary.tsx`, `OitFltOpsBoxes.tsx` (src/ops_pages.rs), the NssAvncs CompanyCom, Maintenance and FbwSystems pages (src/avncs.rs).

- T.O PERF: `ToPerfModel.compute` (pressed, SimBrief TLR phase, TLR weight units, calibration, engine rating) makes the results come from raw inputs: the TLR entry for the selected runway when present, otherwise `takeoff()` with the dropdown texts, weather, weights and runway. The old `results` strings still work when `compute` is absent (captures).
- LDG PERF: `LdgPerfModel`, results derived by `ldg_results` (TLR landing report and `landing()`).
- IN-FLT PERF: `InFltModel` holds the stepper inputs and live data; `inflight_rows` gives the module rows; `learn_flight_model` is the FM calibration learner.
- LOADSHEET: `LoadsheetInput` (raw SimVar values) to `build_loadsheet`.
- AVNCS: `Avncs.page` is `menu`, `company_com` (inbox, flight log), `maintenance` (report current/post/by ATA, system status, logbook, remote C/B), `fbw_systems` (app and ldg capability decoded from raw ARINC words, FWS debug).

Tests: `cargo test --release` in crates/oit_pages. `tests/perf_oracle.rs` compares against `tests/fixtures/perf_oracle.json`, written by `node tools/perf_oracle.mjs`, which bundles FBW's PerfModel.ts and InFlightPerf.ts with esbuild and runs 8 take-offs, 4 landings, 160 VLS points and 16 in-flight scenarios (relative tolerance 1e-9, limits lists and integer speeds exact). `tests/pages.rs` holds the page-tree tests for pages without captures.

Pages without a capture (trees built from source, structure asserted in tests/pages.rs): LDG PERF, IN-FLT PERF, LOADSHEET, OPS LIBRARY, LOAD BOX, EXPORT BOX, AVNCS COMPANY COM (menu, inbox, flight log), MAINTENANCE (menu, reports, system status, logbook, remote C/B), A380X SYSTEMS (menu, app and ldg capability, FWS debug). T.O PERF computed results are also not in any capture. These need a capture to verify class by class.
