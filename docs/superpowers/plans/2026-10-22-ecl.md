# Native ECL (normal checklists) and EFB mirror

Source: FBW `FwsNormalChecklists.ts`, `ProcedureLinesGenerator.ts`, `FwsCore.ts` (A380X). Code: `crates/fws_ecl/src/ecl.rs`, `crates/fws_ecl/src/mirror.rs`.

## Done

- Data: 14 normal checklists, 42 items, sensed flags and the FBW condition expressions were already generated into `normal_data.rs`.
- `ecl::sensed_items(id, &SensedInputs, RudderTrimSensing)` reproduces `FwsNormalChecklists.sensedItems` per checklist (None = not sensed). `RudderTrimSensing::Absolute` is the default (the port's `Math.abs` SourcePatch, see docs/ecl.md); `SignedAsFbw` is FBW as shipped and is what the oracle uses.
- `ecl::Ecl` is the state machine, one call to `update(&CycleInputs)` per FWS cycle (FBW: 125 ms throttler):
  - C/L toggles the display and returns to the menu; CHECK on the menu opens the highlighted checklist; CHECK on an unsensed item toggles it and moves down; sensed items cannot be ticked by hand.
  - C/L COMPLETE ticks all unsensed items, completes the checklist and closes the ECL. RESET un-ticks unsensed items and resets every later checklist (manual reset flag).
  - Sensed items are copied into the checklist state only while the ECL is shown (FBW behaviour); a newly sensed tick on the selected line moves the selection down (FBW applies this across checklists by index, reproduced).
  - Take-off power rising edge resets every checklist after `<<DEPARTURE CHANGE>>`; `on_startup_completed` and `on_shutdown_50_minutes` reproduce FwsCore's resets; flight phase != 1 clears the manual-reset flag.
  - Deferred checklists (1000007/8/9/11) appear in the menu from `DeferredStatus`, now derived each cycle from `Ecl::deferred_procs` (FwsCore `activeDeferredProceduresList`, insertion order). The open procedure keeps FBW's stale copy semantics (`gen_state`).
- Deferred procedure pages (`crates/fws_ecl/src/deferred.rs` + `Ecl`, data from `fws_data::DEFERRED`): one generator per visible procedure of the page type with its own selection piped to the ECL line (FBW pipe semantics: the line only follows when the generator's index changes), ACTIVATE (-2), item ticks with `conditionalActiveItems`, DEFERRED PROC COMPLETE (-3) / RECALL (-4), page CLEAR (-99, CHECK returns to the menu), UP/DOWN across procedures, page rebuild when the active procedure leaves the list (FBW `checklistId.notify()`, including its quirk of resetting a normal page's selection to 0).
  - FwsCore side as functions the fws crate calls: `core_add_deferred` (procedure presented: not activated, `conditionalActiveItems` on the initial vector), `core_update_deferred` (per-cycle refresh: sensed items from `whichItemsChecked`, `whichItemsActive` or all = activated, change detection as FBW), `core_retain_deferred` / `core_clear_deferred` (also called from `on_startup_completed` / `on_shutdown_50_minutes`).
- `mirror::EclMirror::from_ecl(&ecl, &live)` (serde behind feature `serde`) gives the EFB page: per checklist `efb_page_id` (`"n:<index>"`, the ids `app/ui/index.html` already uses for `DOCS.normal`), title, menu visibility, completed, and per item name/value/level/headline/sensed/checked plus `sensed_now` (live value while the ECL is closed). `efb_ticks("n:i")` returns the item indices for `docTicks`.

## Oracle

Scenario `tools/fws_oracle/scenarios/ecl_normal_walk.json` (generated: emu-04-apu, then C/L, CHECK_LH, DOWN, CLR presses and switch changes from COCKPIT PREPARATION to SECURING THE AIRCRAFT, then RESET). Recorded with the existing `fws_oracle_test.exe` into `E:/fbw-build/ecl39/oracle/`. Buttons are held 200 ms and released 300 ms; shorter presses get merged by FBW's 125 ms cycle.

`tests/ecl_oracle.rs` replays the scenario's inputs (ARINC words decoded, FWS cycle every 125 ms with buffered buttons) and compares shown / open id / selected line / every checklist's itemsChecked and completed / every deferred procedure's activated, completed, itemsChecked, itemsActive against the FBW bus after each settled tick (450 ms after the last input change). The deferred list is seeded from the bus only when FBW adds or removes an entry (core presentation); the per-cycle refresh runs in Rust. The abnormal-sensed-shown input is taken as of the previous FWS cycle (FBW reads it before its own CLR handling).

- `ecl_normal_walk`: 866 ticks, 129 compared, 0 mismatches, now through the AT TOP OF DESCENT deferred page (snapshot carries 221700001), PARKING, SECURING and RESET.
- `ecl_complete_reset` (`tools/fws_oracle/scenarios/ecl_complete_reset.json`, golden `E:/fbw-build/ecl49/oracle/`, generator and landing checker in `E:/fbw-build/ecl49/tools/`): presses held 200 ms, released 600 ms. Lands on C/L COMPLETE of every normal checklist (65 of 65 intended FBW selections hit, checked against the bus), covers DOWN to RESET / UP back, un-tick, RESET of a completed checklist reopened from the menu, RESET of an incomplete checklist, RESET cascading to later checklists, the deferred page (ACTIVATE, DOWN/UP through page CLEAR, un-tick, PROC COMPLETE, RECALL, COMPLETE again, CLEAR to menu), CLR to menu and CLR close. 1614 ticks, 337 compared, 0 mismatches. Every normal checklist and the deferred procedure reach completed in the FBW bus.

Note: FBW stores some sensed values as numbers (`GetSimVarValue(..., 'bool')` returns 1), so its bus shows `1` instead of `true` for APPROACH/LANDING SEAT BELTS and BEFORE START BEACON; the harness treats them as truthy.
