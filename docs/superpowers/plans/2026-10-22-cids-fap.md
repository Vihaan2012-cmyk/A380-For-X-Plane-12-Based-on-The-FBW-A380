# CIDS and FAP completeness (cids30)

Date: 22 October 2026. Scope: the A380 Cabin Intercommunication Data System (CIDS) and the Flight Attendant Panel (FAP) in the X-Plane port, the cockpit-side CALLS / EMER / EVAC controls, and the gap between what exists and what the public descriptions of the real system do. The new logic lives in `crates/cids` (std only, no plugin dependency). Plugin `src/` was read, not edited. FBW's own sources were read only: they contain no CIDS or FAP logic (the A380X FWS only reads `A32NX_EVAC_COMMAND_TOGGLE`, FwsCore.ts 5197, and plays the evac horn from sound.xml 1055).

## 2. What the real A380 CIDS and FAP do (public descriptions only)

Architecture: three CIDS directors (computers; one active, others hot standby), decoder/encoder units, several FAPs (touch screen plus hard keys at the purser and door stations), additional attendant panels, handsets, and four audio channels (PA upper, main, lower decks and the interphone). Functions: cabin lighting, signs, PA / pre-recorded announcements and boarding music (PRAM), interphone and call system, door and slide status, smoke detection display, water/waste, temperature selection, cabin ready, evacuation signalling, emergency lighting control, and a maintenance / test function.

FAP pages named in the task: CABIN STATUS, DOORS/SLIDES, LIGHTS, CABIN TEMPERATURE, WATER/WASTE, AUDIO/PA (pre-recorded announcements, boarding music), CALLS, SMOKE, EVAC, SYSTEMS, MAINTENANCE. Cockpit side: overhead CALLS panel (MECH, ALL, FWD, AFT, PURS held; EMER covered pb), EVAC panel (covered CMD, HORN SHUT OFF, CAPT / CAPT&PURS selector), cabin ready signal to the cockpit, seat belt / no smoking / emergency exit light switches and their automatic functions.

Where an exact tone, timing or threshold is not public, the crate uses a plain generic value and says so below (section 4).

## 3. Gaps found (before this work)

1. No cockpit-to-cabin calls: the CALLS pbs (ALL/FWD/AFT/PURS) light nothing and ring nothing in the cabin; MECH never sounds a nose-gear horn; ground mech call never lights the cockpit pb.
2. No cabin-to-cockpit calls reach the cockpit: no chimes, no call light, no EMER CALL; `deep/cabin/crew_calls.rs` is isolated and only publishes a priority/count that the FAP shows as `CALL n`.
3. EMER pb (`A32NX_CALLS_EMER_ON`) has no effect in the cabin.
4. EVAC: the FAP writes `A32NX_EVAC_COMMAND_TOGGLE` directly. It ignores the CAPT / CAPT&PURS selector, EVAC RESET clears the cockpit command even when the pilots set it, no cabin-side alert state (flashing EVAC, cabin horn), the horn shut off only works inside sound.xml, no forced emergency lights / full bright cabin, announcements and music are not cancelled.
5. SMOKE RESET key is wired to the CALL RESET sequence (a mislabel); there is no smoke horn, no latching, no automatic emergency call, and cargo smoke is only a caution word.
6. Doors page: no warning when a door is opened with its slide armed, no departure / approach slide-armed caution, no refusal for residual cabin pressure (>= 0.8 psi) or armed slide, no cargo door slide handling.
7. Cabin ready: the FAP sets `CABIN_READY` and nothing ever clears it (door opened, climb, taxi-in); no checklist; no chime to the cockpit.
8. Signs: only the seat belt AUTO rule; no NO SMOKING AUTO (gear), no excess cabin altitude forcing (11,300 ft), no sign chime, no emergency-light logic (ARMED on power loss, FAP override, cockpit OFF priority).
9. PA: no source priority (cockpit PA, attendant handset, pre-recorded, music), no per-deck availability from the deep CIDS channel faults, no ducking of music, no auto-stop of boarding music, no stop-persists-until-doors-close.
10. CIDS directors: nothing models director 1/2/3 switchover, boot time, or CIDS FAULT behaviour (FAP shows the three fault flags only). When all three are lost the FAP should blank its functions and the hard-wired ones (signs from cockpit switches, EMER pb) should still work.
11. Missing FAP pages: CALLS (call log), EVAC (command status), MAINTENANCE (lamp / PA / director tests; allowed on the ground, brake on, engines off). Existing LAV MAINT and 30 s LOCK keys are cosmetic stubs in the JS.
12. FAP touch lock and screen-off: hard keys must still work while locked or off (the JS locks everything).
13. Temperature: single `PURS_SEL_TEMPERATURE` bump of 0.5 with no per-area setpoints (six areas) and no selector fault handling.
14. No automatic emergency-class cockpit call from cabin smoke / IFE / galley detection.

## 4. What was built: `crates/cids`

Standalone crate (own `Cargo.toml` with an empty `[workspace]`, no dependencies), 47 tests, `cargo test` green and clippy clean apart from one `too_many_arguments` on `Calls::step`. Pure logic: `Cids::update(&Inputs, dt) -> &Outputs`, `Cids::view() -> FapView`.

Modules:

| Module | Role |
|---|---|
| `types` | inputs (`Cockpit`, `Power`, `Flight`, `DoorIn` x18, `CabinIn`, `Crew` with `Event` list), enums, `Config` |
| `phase` | Parked, TaxiOut, TakeoffRoll, Climb, Cruise, Descent, Approach, Rollout, TaxiIn from raw flight data |
| `directors` | 3 directors, lowest healthy active, sticky, 8 s start, degraded / failed |
| `calls` | MECH / ALL / FWD / AFT / PURS from the cockpit, attendant / purser / emergency from the cabin, ground mech call, EMER pb repeating chime, latches, call light timeout, call log, `CALL RESET` |
| `evac` | cockpit CMD + FAP CMD with a 3 s guard, CAPT-only refusal, cockpit horn shut off, EVAC RESET (refused while the cockpit command is on), cabin horn + red flash |
| `signs` | seat belt (OFF/AUTO/ON), no smoking (gear in AUTO), 11,300 ft forcing, sign chime, emergency lights (OFF/ARMED/ON, power loss, evac, FAP switch), exit signs |
| `pa` | source priority cockpit > handset > pre-recorded > music, per-deck availability, music ducking, boarding music auto start/stop, stop persists until doors close, scheduler request 1 = music |
| `doors` | FAP door interlocks (stationary, engines off, residual pressure, armed slide), door / slide views, open-with-slide-armed warning, slides-not-armed caution, door open in departure, latch / slide pressure faults |
| `smoke` | 14 detection locations (lav, galley, IFE, cargo x3, crew rest), horn, reset, automatic emergency call for non-cargo smoke |
| `ready` | six area confirmations, checklist, optional strict mode, resets on door open and on flight stage change, cockpit chime |
| `temp` | six area setpoints, 18-30 C in 0.5 C steps, purser selector fault |
| `maint` | lamp / PA / director tests, ground + brake only, pass/fail with reason |
| `fap` | FAP unit: power-up boot (9 s), PC RESET, screen off, 30 s lock (touch only), page navigation, switch states |
| `view` | `FapView`: mode, header, top-3 cautions, message line, hard keys, switches, and a typed `PageBody` for all 14 pages |

Generic (not public) values, chosen to be easy to change in `Config` or the module constants: chime to meaning mapping, 6 s emergency chime repeat, 30 s call-light hold, 25 s announcement length, 3 s evac guard, 8 s director start, test durations. The crate emits abstract `ChimeKind`s; the plugin maps them to sound ids.

## 6. FAP page work (native page tree)

The JS FAP stays working until the native version replaces it. Native follows the MFD / OIT pattern: a `crates/fap_pages` (or a module in `crates/oit_pages`) takes `cids::view::FapView` and builds `mfd_tree::Node` trees (`Node::el` / `class_if` / `child`), one builder per `PageBody` variant, with the same 800x600 layout and colours as `fap.js`:

1. Shell: header (title), caution line (3 entries, red / amber / cyan), message line, hard key column (`FapView.keys`: lit / alert / guard states), the two switches, nav strip over `Page::ALL` (14 pages: the 11 existing plus CALLS, EVACUATION, MAINTENANCE), BOOTING and DARK / SCREEN OFF modes (`ViewMode`), locked indicator.
2. Per page: Status rows, Music, Pre-announcement (selected, remaining time, deck availability), Lights (scene grid, level slider, sign / emergency light state), Doors (plan view from `DoorView`, slide colours as `COLOURS` in fap.js), Temp (six areas, set vs actual), Water/Waste, Smoke (14 locations + horn), Seat Setting, Cabin Ready (six areas + checklist + incomplete hint), System Info (directors, channels), Calls (log), Evac (cockpit / cabin command, CAPT selection, horn), Maintenance (tests and result).
3. Touch: map taps to `cids::Event` through the same event channel as the instrument (`A380X_FAP_EVENT`), so the JS and the native page can run side by side.
4. Golden check: screenshot the JS FAP in each state (`tools/golden-tour`), then match the native tree to it before removing the JS page.

### Status (fap32, 22 October)

Done: `crates/fap_pages` (own `[workspace]`, path deps `mfd_tree` + `cids`). `fap_root(&FapView, &FapSim, &Ui) -> Node` builds `#FAP_ROOT > #SCR + #HK` with one builder per `PageBody` variant (`pages.rs`: the 11 existing pages, `extra.rs`: CALLS, EVACUATION, MAINTENANCE and the CIDS FAULT body), the shell (header, caution spans, Screen Off key, nav strip, message and lock lines, hard keys, EMER LIGHT / PAX SYS switches) and the DARK / BOOTING / SCREEN OFF modes. `FapSim::read(get)` reads the same sim values `fap.js` reads (zone temps, water/waste, galley, IFE, door percent/disarm); pages use the `PageBody` state where it carries it (music, pre-ann selection, scene/level, doors, ready areas, seat power, directors) and `FapSim` for the rest. `FAP_CSS` exports `fap.css` for the cascade. `Ui.nav` is `Page::ALL` (14, narrower keys) in production and `LEGACY_NAV` (11) for the reference match.

Reference: `E:/fbw-build/fap-native/capture.mjs` serves `html_ui` plus a harness page (stubbed `SimVar` / `BaseInstrument` from `fixture.json`) to headless Edge on port 9446 with its own profile, and writes `ref/<page>.dom.html` + `.png` for the 11 pages. `compare_all.sh` builds `fap_dump`, dumps each page from the same fixture and runs `tools/pagetree/compare.py ... id=FAP_ROOT`: 0 differences on all 11 (123-191 golden nodes each). 11 unit tests (shell, modes, nav, CALLS / EVAC / MAINTENANCE states, door reading, plan SVG).

Left: touch mapping (`data-a` actions are not carried by `mfd_tree::Node`; the host needs a hit table per page), SVG text labels (door names, temperature chip labels) and the lights wedge gradient are not emitted (the DOM reference drops SVG text too), the TEMP / SMOKE pages still show the `fap.js` zones rather than the six `cids` areas and 14 smoke locations, host wiring and in-sim check.

## 7. Open items and risks

- Chime semantics, emergency repeat period, announcement lengths and the area list (six areas) are generic until real references are available.
- The CAPT / CAPT&PURS selector polarity and the exact authority for the cabin EVAC RESET are from public training descriptions; both are single-line changes in `evac.rs`.
- Nothing here is verified in the simulator. The crate is tested only as logic.
- The PURS call pb shares a hold var with AFT in the converted cockpit XML (an upstream conversion quirk); the host will see PURS as AFT until the var is split.
