# Ops: full-zone weight and balance, boarding, refuel, wear switch, simulated AOC

Crate: `crates/ops` (own `[workspace]`, serde only). 15 tests pass
(`CARGO_TARGET_DIR=E:/fbw-build/target cargo test --offline` in the crate).
Nothing is wired into the plugin yet. This plan lists the hooks.

## What exists (audit, 22 Oct)

- `src/mass_balance.rs` / `src/weight_balance.rs`: parse FlyByWire's
  `flight_model.cfg` stations and tanks, sum moments, and write X-Plane's
  `m_stations` / `cg_offset_z`. Publishes `fbw/wb/payload_kg`,
  `gross_weight_kg`, `cg_z_ft`. No % MAC and no THS.
- FlyByWire's own `A380Payload` (boarding agents, BOARDING_RATE) and
  `A380Airframe` (writes `A32NX_AIRFRAME_{ZFW,GW,TO}_CG_PERCENT_MAC`) run
  inside the plugin. FBW sets TOW = GW (taxi fuel TODO).
- `src/study/loadsheet.rs`: the Study loadsheet page, its own copy of the 14
  zones / 3 holds, `KG_PER_PAX` 84; writable `BOARDING_STARTED_BY_USR`,
  `BOARDING_RATE`, `REFUEL_STARTED_BY_USR`.
- `src/efb.rs:434-437`: EFB settings `CONFIG_USING_METRIC_UNIT`,
  `REFUEL_RATE_SETTING` (FBW `A32NX_EFB_REFUEL_RATE_SETTING`, read by
  CPIOM-F), `CONFIG_BOARDING_RATE` (`A32NX_BOARDING_RATE`).
- `crates/fuel_mgmt/src/model.rs`: same 11 tanks; its `CgModel` uses a
  GENERIC 12.36 m MAC with 40 % origin, not FBW's LEMAC 21.09 ft / MAC
  40.35 ft. It should take `ops::aircraft::percent_mac` instead (follow-up,
  not done here).
- Random failures: `src/app_settings.rs` `randomFailures` / `failure_rate`
  feeds `src/random_failures.rs`. Wear/exceedance arming lives in
  `src/physics/damage.rs` (`arm`, line ~730) with persistent wear in
  `src/wear.rs`. There is no on/off switch for wear-driven failures.
- Gates: `src/navdata/apt.rs::gates` reads apt.dat 1300 rows (name,
  position).
- AOC: `crates/datalink/src/aoc.rs` `Aoc::received_freetext(AnyMessage)`
  (read only; not changed).

## Crate API

- `aircraft`: `PAX_ZONES`, `HOLDS`, `TANKS`, `Door`, `percent_mac`, limits.
- `loadsheet`: `Load` (pax per zone, cargo per hold, fuel per tank, pax kg,
  taxi and trip fuel) -> `Loadsheet` (ZFW/GW/TOW/LW, CGs, THS, limit flags).
- `trim`: `ths_for_cg`, `cg_for_ths`, `ths_in_cyan_band`.
- `boarding`: `Boarding::new(pax, cargo, doors, speed)`, `set_target`,
  `step(dt)`, `estimate_seconds`; `doors_in_use(jet_bridges, stairs)`.
- `refuel`: `distribute(total_kg, trim_kg)`, `Refuel::step(dt)`,
  `estimate_seconds`, `rate_kg_per_s(speed, source)`.
- `aoc`: `AocSim::on_event(now, Event)`, `poll(now) -> Vec<Uplink>`,
  `gate_from_spot`, `loadsheet_text`.
- `settings`: `OpsSettings` (camelCase serde: `units`, `boarding`,
  `refuel`, `fuelSource`, `wearFailures`, `simulatedAoc`, `paxKg`),
  `resolved_units(airline_icao)`, `aoc_active(on_network)`.

## Hooks (for the owner of each shared file)

1. Root `Cargo.toml`: add `ops = { path = "crates/ops" }`.
2. `src/app_settings.rs`: add the `OpsSettings` fields with the camelCase
   keys above (defaults: airline units, realistic boarding/refuel, hydrant,
   wear failures on, simulated AOC on, 84 kg).
3. Boarding (b): map `boarding` to FBW's `A32NX_BOARDING_RATE` (Realistic 2,
   Fast 1, Instant 0) through `efb.rs`'s existing `CONFIG_BOARDING_RATE`;
   FBW's PayloadManager keeps doing the boarding. Open the doors in use
   (`INTERACTIVE POINT OPEN:0/2/6/8/10`) from the jet bridges docked
   (OJE / native jetways) plus stairs, so FBW's agents match. Use
   `Boarding::estimate_seconds` only for the EFB ETA.
4. Refuel (c): map `refuel` to `A32NX_EFB_REFUEL_RATE_SETTING` (FBW
   `RefuelRate` in fbw-common systems/src/fuel/mod.rs: Real 0, Fast 1,
   Instant 2). Truck source has no FBW equivalent: when Truck +
   Realistic, the plugin pauses FBW's refuel and drives tanks with
   `ops::refuel::Refuel` at the truck rate, or drop Truck if not wanted.
5. Weight and balance (a): `weight_balance.rs` builds a `Load` from FBW's
   per-zone `A32NX_PAX_*`, `A32NX_CARGO_*` and the 11 tank weights, plus the
   taxi/trip fuel from the FMS, and publishes `fbw/wb/zfw_cg_mac`,
   `fbw/wb/tow_cg_mac`, `fbw/wb/ths_deg`. THS: write FBW's take-off trim
   target (`setTakeoffTrim` path in FmcAircraftInterface.ts) from
   `Loadsheet::ths_deg` when the MFD T.O THS field is empty; never move the
   THS while the flyer is trimming. Units: `resolved_units(livery airline
   ICAO)` -> `CONFIG_USING_METRIC_UNIT`, EFB override wins.
6. Wear failures (d): `physics/damage.rs::arm` returns early for
   wear-driven ids when `wearFailures` is off; exceedance damage
   (overspeed, hard landing, FOD) stays on, as do manual and scheduled
   failures. Persistent wear still accumulates so turning it back on is
   honest.
7. Simulated AOC (e): a small `src/ops_aoc.rs` owns `AocSim`; each frame,
   if `aoc_active(online network connected)`, `poll(utc_s)` and for each
   uplink build a `FreetextMessage` (direction Uplink, station = `Uplink::station`,
   message = text) and call `Aoc::received_freetext`. Events: flight init
   from the FMS/SimBrief OFP (airline, number, origin, destination, STD)
   with the parking spot from `navdata/apt.rs::gates` nearest the aircraft;
   boarding started/complete from FBW's boarding L:vars (complete carries
   `Loadsheet::compute` and resolved units); OOOI from the existing ACARS
   OOOI detection (parking brake / doors, take-off, touchdown, in); arrival
   gate from the nearest destination gate after landing.
8. EFB (app/ui): Settings > Ground ops rows: Weight units (Airline / KG /
   LB), Boarding (Realistic / Fast / Instant, ETA shown), Refuel (Realistic /
   Fast / Instant, Hydrant / Truck), Wear-driven failures (On / Off),
   Company messages when offline (On / Off). Pages: Payload with 14 zones on
   two decks + 3 holds; Fuel per tank (from `distribute`); Loadsheet with
   ZFW/TOW/LW, ZFWCG/TOWCG, THS and limit flags; all in the resolved units.
9. Dedupe: `src/study/loadsheet.rs` zones/holds and `fuel_mgmt::CgModel`
   take their tables from `ops::aircraft`.
